# Primer cliente: Jaditek Sim Racing

El módulo pertenece a **San Rafael 360**.  
**Jaditek Sim Racing** es el comercio que lo usa primero (no el dueño del código).

Contexto del **local físico** (hardware, otros sistemas del salón, competencia): repo hermano **Jaditek-SimR**.  
Allí CMP-01 (reservas) solo **apunta** a esta documentación.

## Configuración acordada (MVP)

| Tema | Valor |
|------|--------|
| Recursos | **4 puestos** (simuladores); el motor los trata como recursos genéricos |
| Duración vendible | **1 hora** |
| Llegada | Recomendar **15 min antes** (charla en living); texto en la página/confirmación |
| Online | Link de reservas → grilla → pago → firme |
| Admin | **Diego** y **María Laura** solamente (lista fija) |
| Admin puede | Alta en persona + **bloquear** tiempo |
| Cancelación | Hasta **24 h antes** con **reembolso**; libera el hueco |
| Mercado Pago | Cuenta **Jaditek** (ellos son el comercio) |
| Buffer limpieza entre horas | No definido aún; por ahora no automático |

## Qué no pide Jaditek al módulo (otros componentes del local)

Cola en sala, auriculares, lanzador del juego, telemetría, etc. viven en el proyecto del local / otros sistemas. El módulo solo asegura **quién tiene el turno pago y cuándo**.

## Evolución

Cuando un segundo comercio de la guía contrate el módulo, se agrega otro “comercio” con sus recursos y (probablemente) su propia cuenta Mercado Pago. Jaditek sigue siendo un cliente más.
