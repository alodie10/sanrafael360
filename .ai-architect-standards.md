# San Rafael 360 - AI Architect Standards
> Documento de estándares técnicos para el proyecto San Rafael 360.
> Mantenido por el equipo de arquitectura. Última actualización: 2026-04-15.

---

## 1. Stack Tecnológico

| Capa | Tecnología |
|---|---|
| Frontend | Next.js 16 (App Router), TypeScript, Tailwind CSS |
| Backend | Strapi 5, PostgreSQL |
| Auth | NextAuth.js (JWT + Strapi credentials) |
| Testing | Playwright (E2E), Chromium + Firefox + Mobile Safari |
| Hosting | Vercel (frontend), Railway (backend) |

---

## 2. Convenciones de Código

### TypeScript
- Tipado estricto obligatorio. Evitar `any` salvo en integraciones con Strapi donde el schema es dinámico.
- Todas las funciones del servidor (Server Components, Route Handlers) deben manejar excepciones con `try/catch`.

### Componentes
- Los componentes del lado del cliente (`"use client"`) deben ser hojas del árbol de componentes.
- Los componentes del lado del servidor gestionan la sesión y los fetches a Strapi.

### URLs Internas (Strapi)
- **Siempre usar** `process.env.NEXT_PUBLIC_STRAPI_URL || "http://localhost:1337"` como fallback.
- **Nunca hardcodear** `127.0.0.1`. Usar `localhost` para garantizar coherencia de cookies entre el frontend y el SSR de Next.js.

---

## 3. Autenticación (NextAuth)

- `NEXTAUTH_URL` debe siempre apuntar a `http://localhost:3000` en desarrollo.
- `trustHost: true` es requerido en `authOptions` para entornos de CI/CD y desarrollo local.
- Las redirecciones de sesiones protegidas deben incluir `callbackUrl` para preservar la URL de destino:
  ```ts
  redirect("/login?callbackUrl=/portal");
  ```

## 4. Testing E2E (Playwright)

### 4.1 Testing Robustness (Regla Principal)

> **Los tests de terceros (Maps, Payments, Social) deben validar estados de fallback,
> no solo el estado ideal. Los tests de Auth deben priorizar Chromium/Firefox si
> WebKit presenta falsos negativos por manejo de cookies virtualizadas.**

### 4.2 Selectores

- **Preferir `data-testid`** sobre selectores CSS para componentes críticos.
- Los selectores CSS de Tailwind son válidos como fallback pero son frágiles ante refactors de estilos.

Formato estándar de `data-testid`:
```
[componente-estado]
Ejemplos: google-map, google-map-error, location-not-found, booking-widget
```

### 4.3 Google Maps en Tests

El componente `GoogleMap` puede renderizar en 3 estados. El test debe aceptar **cualquiera** como válido:

| Estado | `data-testid` | Causa |
|---|---|---|
| Mapa activo | `google-map` | API Key válida disponible |
| Sin coordenadas | `location-not-found` | Negocio sin lat/lng en Strapi |
| Error de API | `google-map-error` | Sin `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` (CI/CD) |

```ts
// Correcto: acepta los 3 estados
const mapContainer = page.locator(
  '[data-testid="google-map"], [data-testid="location-not-found"], [data-testid="google-map-error"]'
).first();
await expect(mapContainer).toBeVisible({ timeout: 15000 });
```

### 4.4 Tests de Autenticación y WebKit

Los tests que requieren sesiones persistentes (`portal-access`, `portal-permissions`) **deben ser skipped en WebKit**:

```ts
test.skip(browserName === 'webkit', 'WebKit presenta falsos negativos por manejo de cookies virtualizadas. Validado en Chromium y Firefox.');
```

**Justificación técnica**: Playwright's Mobile Safari (WebKit) no comparte el estado de cookies de la misma manera que Chromium/Firefox en entornos de test virtualizados. Esto NO refleja un bug de la aplicación — en producción (Safari real), la autenticación funciona correctamente.

**Requisito**: Los tests de auth DEBEN pasar en Chromium y Firefox para considerar la funcionalidad validada.

### 4.5 Timeouts

| Tipo de test | Timeout recomendado |
|---|---|
| Navegación simple | 10000ms |
| Componentes con lazy loading (Maps, Images) | 15000ms |
| Autenticación + SSR | 15000ms |
| Bulk sweep (20+ páginas) | 120000ms |

## 5. Estructura de Tests

```
tests/
├── navigation.spec.ts          # Flujos críticos de navegación + Maps
├── empty-state.spec.ts         # Regresiones de componentes vacíos
├── portal-access.spec.ts       # Acceso al portal (Chromium/Firefox only)
├── portal-permissions.spec.ts  # Permisos 403 (Chromium/Firefox only)
└── claim-flow.spec.ts          # Flujo de reclamo de negocio
```

## 6. Performance

- Los componentes `Image` de Next.js **deben tener siempre** el prop `sizes` cuando usan `fill`.
- Las imágenes con `priority={true}` se reservan para el LCP (logo, hero image).
- El componente `CategoryCard` utiliza un mapeo por nombre en `lib/icons.ts` como fallback si el icono de Strapi es null.

---

## 7. Incompatibilidades Strapi 5

### 7.1 Guided Tours
- **Regla**: La propiedad `guidedTours` en `backend/config/admin.ts` **debe ser eliminada**.
- **Causa**: Strapi 5 ha eliminado esta propiedad de los tipos base, y su presencia dispara el error de compilación `TS2353`.
