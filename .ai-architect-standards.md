# .ai-architect-standards.md

Este archivo contiene los estándares de arquitectura y robustez acordados entre el AI Architect y el Agente de Desarrollo. Son de cumplimiento obligatorio para todas las propuestas y ejecuciones.

## 🛡️ Reglas de Oro de Arquitectura

1. **Robustez de Inicio:**
   - Ningún plugin de terceros (Resend, Scrapers, etc.) debe impedir que Strapi inicie.
   - Usa siempre valores por defecto (placeholders) en las inicializaciones de environment variables críticas.
   - Implementa bloques `try/catch` defensivos en todos los puntos de entrada de plugins.

2. **Desacoplamiento de Procesos:**
   - Los procesos pesados o de larga duración (Playwright, envíos de email masivos) deben ser **asíncronos** y no bloqueantes para el flujo principal del usuario.
   - Usa patrones de "Fire & Forget" o colas de mensajes si están disponibles.

3. **Soberanía y Estabilidad de Datos:**
   - Antes de migrar a APIs nuevas o experimentales (ej: v5 Document Service), prioriza métodos probados y estables como `strapi.query` si la estabilidad del sistema está en riesgo.

4. **UX de Resiliencia:**
   - Todo botón interactivo que dispare un proceso de carga (ej: "Enviando...") de contar con un bloque `finally` que restaure el estado de la UI (loading: false), independientemente de que el servidor responda con éxito o falle.

24. **Manejo de Errores en Endpoints:**
    - Todo endpoint personalizado debe estar envuelto en un bloque `try/catch`.
    - En caso de fallo en consultas de listado (ej: `/me`), el controlador debe retornar un array vacío `[]` con Status 200 para evitar que la UI del portal se bloquee con errores 500 inesperados.

6. **Consistencia de Esquemas:**
   - Nunca intentes popular (`populate`) campos o controladores sin verificar físicamente la existencia del `schema.json` correspondiente en la API destino.
   - Tras modificar un esquema, se debe asegurar la regeneración de tipos de TypeScript para evitar fallos de compilación.

## 🪜 Protocolo de Escalado a Architect

Si un error persiste por más de **2 intentos**, el Desarrollador (Antigravity) deberá:
1.  **Cesar Intentos:** No intentar una tercera solución a ciegas.
2.  **Reporte Técnico:** Redactar un resumen con:
    - Estado actual del código.
    - Logs de error (Railway/Consola).
    - Hipótesis de por qué fallaron los intentos anteriores.
3.  **Consulta Externa:** Solicitar explícitamente: *"Por favor, consulta con el Architect este resumen"*.
4.  **Ejecución Dirigida:** Aplicar la respuesta del Architect literalmente.
5.  **Capitalización:** Guardar la solución en este archivo como "Lección Aprendida".

*   **2026-04-09 [TS Build Fix]:** Al crear nuevas APIs en Strapi 5 con TS, el UID de la API puede no estar en el registro global de tipos durante el primer build. Casting a `any` en `factories.createCore...` previene bloqueos de compilación en CI/CD (Railway).
*   **2026-04-09 [Defensive Plugins]:** El constructor de `Resend` lanza excepciones fatales si la API Key es `undefined`. Siempre proveer un default string para evitar Crash Loops en el servidor.
